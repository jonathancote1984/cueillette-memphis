## Verdict de spécificité — ancré, non interchangeable

- **Conceptuel ~90 %** : « coins secrets », centre antipoison 1-800-463-5060, gyromitre vs morille, français du Québec tenu partout. Irréductible au domaine.
- **Visuel ~80 %** : système Memphis réellement exécuté (bordures 3 px, coins cassés, ombres dures, zigzag, pois, Fredoka, palette automne/terre, zéro boîte système native vérifié). Réserve : la grammaire visuelle resterait crédible pour un carnet de pêche — la spécificité « champignon » repose sur les emojis et les photos.
- **Scan déterministe** : 5 findings (4 `bounce-easing` l.96/226/229/248 + 1 `side-tab` l.127), tous warning, catégorie slop. **Jugés faux positifs contextuels** vs le style Memphis documenté (bordure noire 3 px = token `--noir`, élastique = ludisme assumé). À documenter dans DESIGN.md plutôt qu'à « corriger ».
- **Overlay** : échec réel — `detect.js` absent du projet → 404 → onerror. Aucun overlay visible ; fallback signalé honnêtement. Console navigateur : **0 erreur JS**.
- **Accords A+B** : les deux confirment l'absence d'aide/onboarding et la surcharge de la feuille d'espèce ; le détecteur n'a rien trouvé que la revue LLM n'ait pas vu (5 slop vs 0 erreur JS), et la revue a trouvé les vrais problèmes (contrastes, import, clé) que le détecteur ne couvre pas.

## Impression générale

Une app chaleureuse, disciplinée et sûre — le Memphis est exécuté jusqu'aux modales, la sécurité est un citoyen de premier rang. La plus grosse opportunité : **débloquer la fonction phare (identification) au moment où elle est exigée**, et alléger la feuille d'espèce.

## Ce qui fonctionne

1. **Le système Memphis est exécuté, pas décoré** — tokens tenus, bordures/ombres/coins cassés déclinés jusque dans les confirmations, états vides et toasts.
2. **La sécurité est un citoyen de premier rang** — alerte MORTEL + antipoison dans la fiche ET le résultat d'identification, filtre « ☠️ Mortels », prompt IA forcé à « inconnu » en cas de doute, double confirmation d'effacement.
3. **Les états vides et l'interaction mobile sont soignés** — états vides chaleureux et guidants, 3 voies de sortie des feuilles, FAB contextuel, GPS one-tap avec précision.

## Problèmes prioritaires

- **[P1] Identification IA : la fonction phare bloque sur une clé introuvable.** Toast 2,2 s avec URL externe ; la clé se configure dans un `<details>` au bas de la feuille d'ajout d'espèce (l.565-569) qu'on n'ouvre jamais pour identifier. *Fix* : bandeau persistant « Configurer la clé → » sur la vue Identifier, ou onboarding au premier lancement. → /impeccable onboard + clarify
- **[P1] Confiance IA affichée sans seuil : fausse réassurance sur un sujet mortel.** « Confiance : 62 % » + badge « Comestible » vert (l.1556). *Fix* : seuils (≥90 % vert, 60-89 % « vérifiez avec le guide », <60 % = inconnu) + rappel règle d'or. → /impeccable harden
- **[P2] L'import écrase tout avec UNE confirmation** (l.1667) vs double pour l'effacement. *Fix* : double confirmation ou résumé avant écrasement. → /impeccable harden
- **[P2] La zone photo ment : le CTA le plus visible est inerte** quand vide (l.1045 ne fait rien sans photo). *Fix* : clic sur zone vide = ouvrir le choix photo. → /impeccable clarify
- **[P2] Contrastes en échec** : noir sur bleu #8A5A2B = 2,91:1, noir sur rose #C1502E = 3,62:1, #0E8F6B sur blanc = 3,78:1, titre header sur dégradé ≈ 2,7:1 (est.). *Fix* : texte blanc sur bleu/rose, assombrir #0E8F6B → #0B7A55. → /impeccable audit
- **[P2] Export enfoui sous « Statistiques »** (l.375) — la seule protection anti-perte n'est pas nommée. *Fix* : entrée « Sauvegarde » nommée ou bandeau « Jamais exporté ». → /impeccable layout

## Red flags par persona

- **Sam (mobile distrait, forêt)** : clique la grande zone photo → rien ; « Appareil photo » → toast éphémère de clé. Pire moment : champignon suspect en main, identification impossible, aucune piste in-app.
- **Casey (form-heavy)** : 13 champs pour une variété ; une cueillette par formulaire, pas de duplication — 20 chanterelles = 20 formulaires.
- **Riley (terrain hors-ligne)** : l'identification IA exige réseau + clé — la fonction phare meurt en forêt sans préavis.

## Observations mineures

- 69 styles inline (tokens d'espacement incomplets) ; couleurs hors palette non documentées (onglets actifs #0B6E96/#B3540B/#0E8F6B/#C2185B, dégradé #9A4A12, alertes #F6DFD2/#F4E3C3) ; badge header non cliquable ; alt="" sur vignettes informatives ; toast 2,2 s trop court pour une URL ; erreur GPS possible en anglais ; « Spot supprimé » agrège plusieurs coins ; masquer une espèce fait perdre les badges des vieilles cueillettes (silencieux).

## Questions à considérer

- Si la photo d'un champignon suspect est le moment le plus critique, pourquoi la première action exige-t-elle une clé API à chercher soi-même ?
- À « Confiance : 62 % », le design doit-il afficher un badge vert — ou une question ?
- « Cueillettes », « Mon journal », « Sorties » : trois mots pour une même entité — lequel est le nom ?
- Le 🗑️ masque (réversible) ou supprime (irréversible) selon le contexte : l'icône doit-elle porter cette différence ?
- L'export JSON est sous « Statistiques » : quel est le coût d'un onglet « Sauvegarde » nommé ?
